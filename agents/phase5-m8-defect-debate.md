# M8 暴露策略缺陷 · 3 专家二次辩论裁决（少数服从多数）

> 触发：M8 端到端回测仅 8 笔、净 -7.77%，未达任何门槛。用户要求"让 3 位专家先讨论，有结果再报告"。
> 参与：A 均值回归派 / B 风险派 / C 高频因子派。规则：多数决；少数派保留意见；裁决为后续行动基准。
> 前置数据（修正口径后）：全 10 币对 1h 口径 ±3σ进/0.5σ出/超时max(3h,1.2H) 未来回归率 2.7%–11.7%（ETH/SOL 6.5%）；corr 0.92–0.988；半衰期中位数 6–9bar vs 全样本均值 407bar；h 越界 912–3554 bar。

## 共识（3:0 一致，直接通过）

1. **P0 修复：M4 `_would_add_position` entry_zscore 口径 bug** —— 三位一致认定这是"持仓卡死→仅 8 笔"的直接根因。
   - 证据：`_would_add_position`（mean_reversion_strategy.py line 259–271）用 `z < entry_zscore` 判加仓区，但 `entry_zscore` 在引擎里实际存 confidence（0–1），不是真实 z（±3）。开仓后 z 继续变深时恒 `<` confidence，正常 0.5σ 回归离场被误判为加仓区而拦截。
   - 修复：判据改用与 z 同口径的入场 z 字段（entry_z），或统一命名（entry_z / entry_conf）；加单测"模拟 z 由 -3 回到 -0.5σ 必须触发离场而非加仓"。
   - 三位一致认为：**bug 未修前，M8 的 -7.77% 与 8 笔样本对任何策略判断都无效（GIGO）**。

2. **半衰期口径裁定：统一用中位数（7–9bar），全样本均值 407bar 仅作数据健康度告警** —— 三位一致。
   - 证据：407 vs 7–9 是 50 倍偏态，说明分布重度右偏被离群 bar 支配；中位数才反映"典型回归速度"。
   - 影响：超时窗口与熔断阈值一律用中位数口径；若未来仍要重估 407bar 这个均值本身，说明数据有尾部异常段，属数据层问题而非参数问题。

## 多数裁决（按争议点）

### 争议点 1：h 越界（912–3554 bar 落在 [0.5,2.0] 外）处理
| 专家 | 立场 |
|----|----|
| A | 先重估（更长/稳健窗）从根上减少越界；越界 bar 用钳制（clip 到 [0.5,2] 边界并打降级标记）；INVALID 熔断保留但只用于"数据确实不可用"，不作为 h 数值越界的默认出口 |
| B | 保留 INVALID 熔断作为最后一道闸门（风控底线，不允许关掉）；越界 → 强制重估（30bar 短窗 / winsorize）；仍越界才熔断；越界占比纳入币对健康度指标，高占比币对剔除 |
| C | OLS 60bar 在 1h 尺度对价差序列不收敛（方差大），应改用 EC（Engle-Granger）估计 + 时变平滑；若 EC 也越界，说明因子结构不成立，换估计方法救不了 |

**裁决（2:1，A + B 胜出，C 保留）**：
- 主方案：h 越界 → 强制重估（更短窗 30bar 或 winsorize 稳健化）→ 仍越界则钳制到 [0.5,2] 边界并打降级标记 → 极端场景才 INVALID 熔断
- 附加风控（吸纳 B）：h 越界占比作为币对健康度指标进监控，占比高的币对（BTC/XRP、BTC/SOL）在后续组合筛选中直接剔除
- C 保留 EC 估计作为可选增强，优先级放在主方案修完后

### 争议点 2：下一步方向优先级（修 bug / 换币对 / 修参数 / 换尺度 / 不做）
| 专家 | 排序 |
|----|----|
| A | 修 M4 bug（P0）> 修 h 越界（P1）> 修参数/超时口径（P2）> 换尺度 5m/1m（备选，数据验证后决定）> 不做 > 换币对（corr 已证伪） |
| B | 修 M4 bug（前置硬门槛）> 收紧尺度/参数 > 换币对（剔除 reg_rate 头部 + 越界占比高的）> 参数微调 > 保留"不做"否决权（重测 reg_rate ≥20% 才考虑） |
| C | 修 M4 bug > EC 估计 > 换币对 > 修参数 > **砍掉 1h 统计套利，转做动量因子** |

**裁决（2:1，A + B 胜出，C 保留）**：
1. **修 M4 bug**（P0，三位共识）
2. **修 h 越界**（P1，三位共识，走"重估 + 钳制 + 占比监控"路径）
3. **修参数口径**（P2：超时统一用中位数 H；±3σ 进 / 0.5σ 出 / 单腿 2σ 止损保留，但允许在重测中用样本外数据复核 3σ 是否过稀 —— A 阶段 2 保留意见落地）
4. **换币对**（P3：在修完 1–3 后用重测结果剔除低 reg_rate / 高 h 越界占比币对，只留 XRP/DOGE、SOL/DOGE、BTC/ETH 候选）
5. **换尺度 5m/1m**（P4，作为数据验证后的备选，不抢在主修之前；三位一致不抢跑）
6. **不做 / 转策略**（C 主张，被 2:1 否决，作为"重测后若 reg_rate 仍 <20% 且 EC 也越界"的兜底保留）

### 争议点 3：当前状态可否上线？
**裁决（3:0 一致）：当前不可上线**。
- 三位一致认为：M4 bug 未修 = 上线一个无法离场的系统，敞口裸露、损失无界放大
- 回归率 <12% 的负期望结构 + 8 笔小样本，任何夏普/Calmar 数字都不可信
- 放行条件（重测通过门槛）：修 M4 bug + 修 h 越界 + 中位数口径 + 剔除低 reg_rate/高越界币对 后，重跑 M8 要求 reg_rate ≥20%、回撤 ≤10%、夏普 ≥2.0、Calmar ≥1.5、2024-09 极端段不亏、成本 ≤毛利 35%、连亏 ≤5 笔、足量样本（>30 笔）

## 少数派保留意见

- **C（高频因子派）保留意见**：主张 1h 统计套利的"均值回归半衰期 6–9bar"与"OLS 60bar h 大量越界"本身就是**因子结构不成立**的信号，reg_rate <12% 在 ±3σ 口径下已低于 35% 成本红线，修 bug + 修 h 估计是边际改善而非结构修复。主张在修完 1–2 项后若 reg_rate 仍 <35%，直接砍掉 1h 统计套利 MVP，转做动量因子策略。
  - 三位一致保留此异议作为"重测后的兜底触发器"：重测 reg_rate <35% 且 EC 估计也越界 → 触发 C 的"转策略"路径。
- **B（风险派）保留意见**：保留对"回撤 10% 在 crypto 双币种敞口下偏松、夏普 2.0 未逼出真 alpha"的异议（阶段 2 已记录），主张实盘执行中以回撤 8% 为内部预警线。

## 给阶段的行动清单（按执行顺序）

1. **修 M4 bug**：`mean_reversion_strategy.py` 的 `_would_add_position` 判据从 `z < entry_zscore`（confidence）改为同口径的入场 z 字段；加单测覆盖"z 由 -3 回到 -0.5σ 必须触发离场而非加仓"
2. **修 h 越界**：`h_estimator.py` 加"重估 + 钳制"路径（30bar 短窗 / winsorize）；越界占比进币对健康度监控；INVALID 熔断保留为最后出口
3. **修参数口径**：超时窗口统一用中位数 H（6–9bar）；±3σ 进 / 0.5σ 出 / 单腿 2σ 止损保留，样本外复核
4. **换币对**：在修完 1–3 后重跑 M8，剔除 ETH/SOL（6.5%）、BTC/SOL（2.7%）、BTC/XRP（越界 3554）、ETH/XRP（越界 1303），只留 XRP/DOGE（11.7%）、SOL/DOGE（9.4%）、BTC/ETH（8.3% + corr 0.988）
5. **重测门槛（C 触发器 + B 放行条件）**：reg_rate ≥20%（B 主张）/ ≥35%（C 红线）、回撤 ≤10%、夏普 ≥2.0、Calmar ≥1.5、2024-09 不亏、成本 ≤毛利 35%、连亏 ≤5 笔、样本 >30 笔
6. **触发 C 兜底**：若重测后 reg_rate 仍 <35% 且 EC 估计也越界 → 砍掉 1h 统计套利 MVP，转做动量因子（A/B 暂不反对）
