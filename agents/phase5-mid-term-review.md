## 1. M1–M7 经验教训复盘

### 1.1 做得好的（保留并推广）
- **数据驱动纠正经验**（数据工程师 + PM）：30 天样本初筛锁定 BTC/SOL（EG_p 0.0648），410 天深数据重筛后被 ETH/SOL（EG_p 0.0186、corr 0.982、半衰期 407 bar）纠正。**教训：半衰期/协整判据必须用深数据，短样本会给出错的币对和错的半衰期区间 [24,96]→[368,856]**。这条"以计算结果为准、不凭经验"已被固化进 config 注释。
- **每模块配验收脚本且全绿才提交**（测试工程师）：M1–M7 每个模块都有 `backtest/mX_acceptance.py`，可 1 分钟回归。**推广：M8 必须加"固定种子 + 固定数据 golden value 快照"，防止回测结果随环境漂移**。
- **跨市场 5 接口 + 市场无关骨架**（后端架构师 + PM）：换市场不换骨架，MVP 先做加密 1 套，已按"先 1 套"执行顺序落地 M4/M5/M6/M7 的 ABC 与加密实现类。**收益：M8 主循环无需改动即可复用**。
- **公式红线前置**（代码审查员）：R1–R5（spread=A−hB 非加号 / h 用收益率 OLS / z 用原始价差 σ / t+1 跨 bar / 回撤按净值）在 M3 就逐条落实，M4/M8 受益。

### 1.3 还没对齐的（会上裁决）
- **半衰期 407 bar（≈17 天）远长于原 [25,50] bars 冻结区间**：深数据重筛已把区间修正为 IQR [368,856]，但 M3 信号层构造器默认 `hl_range=(24,96)` 仍是旧值。**裁决：M8 主循环构造 `MeanReversionSignals` 时必须显式传 `hl_range=(368,856)`，否则 ETH/SOL 会被误判 INVALID**（数据工程师）。
- **稳态 vs 峰值收益申报**（B 专家 + C 专家）：因子拥挤/AI 压缩（phase4 §9.1）决定 M8 报告须做"峰值/稳态 0.5×"双栏，单报峰值会高估策略长期价值。
- **M9 是否 MVP 必需**（前端 + 运维）：见 §3。
- **极端段门槛数据缺口**（数据工程师 + 测试工程师，会上发现）：`backtest_gate.must_survive_extreme_window = "2024-09"`，但实际拉的 410 天 1h 深数据窗口为 **2025-09-23 ~ 2026-11-07（9841 bar）**，**物理上不含 2024-09（9·17 闪崩 / 10·11 崩盘）**。该门槛在此数据窗口下无法满足。
  - **用户裁决（2026-11-07）**：把极端段门槛**改写成窗口内真实极端段**——选 **2026-02-04 ~ 02-10**（7 日累计 −25.7%，其中 02-05 单日 −14.0%）作为窗口内最极端段。
  - 已走参数审计留痕改 `strategy_params.yaml`（SHA256 + audit，新校验和 74cc9c3d），`extreme_window_start/end` 落到 config。M8 引擎读 config 而非硬编码。

## 1.5 M8 跑出来的工程缺陷（会前 D8/D9 已识别 + 跑通后新发现）

M8 回测引擎端到端跑通后，**如实暴露 3 个真实缺陷**（不美化、不放宽门槛）：

| # | 缺陷 | 表现 | 处置 |
|---|------|------|------|
| M3-h | h 越界 INVALID 过多 | 410 天 524 bar（5.3%）`hedge_ratio∉[0.5,2.0]` → state=INVALID → 持仓态 M4 `invalid_signal_exit` 反复强平损耗 | h 越界即 INVALID 是 phase2 冻结红线（60bar OLS 估 h 在 0.5~2.0 间频繁越界），**M8 不擅改**，记 M9 优化项（放宽 h_range 或改用对数价差 OLS）|
| M5-regime | regime 拒单率累计熔断 | 一次 INVALID 经 `_check_reject_rate` 触发 halt → 其后 444 单全 HALT，整段熔断 | ✅ M8 已修：regime 类拒单不计入拒单率统计（只有 exposure 类计入），避免统计套利场景偶发 INVALID 熔断整段 |
| 样本薄 | 平仓仅 8 笔 | 410 天 1h + 3σ 进/0.5σ 出 + h 越界拦截 → 成交太薄，统计意义有限 | 如实报告，不美化；需更长数据 / 更宽入场阈值才能改善 |

M8 结果（410 天 ETH/SOL，扣 0.1% taker + 4bp/边滑点，1h 年化 √(365×24)）：
- 净收益（峰值）−7.77% / 稳态（0.5×）−3.88% → **未达 backtest_gate 门槛**（净收益>0 / 夏普≥2.0 / Calmar≥1.5 三项未过）
- 最大回撤 9.79%（≤10% ✅）、跑赢 BTC 单边（−7.77% vs −31.96% ✅）、极端段 2026-02 PnL 0%（✅ 不亏，但该段未持仓，源于 M3-h 缺陷）
- 详见 `backtest/output/m8_backtest_report.md` + `golden_value.json`

**结论**：M8 跑通了全链路 + 如实暴露缺陷，但**策略本身未达冻结门槛**。M8 的价值是"证明管道通 + 量化差距 + 给出优化方向"，而非"证明策略能赚钱"。实盘开关（live_trading）须待 M3-h 修复 + 重新回测达标后开启。

## 2. M8 验收门槛对齐（目标实现）

M8 是项目"是否成立"的唯一裁判，全员确认 M8 出数即定项目去留。

### 2.1 冻结门槛（来自 backtest_gate，须逐条达成）
1. 净收益 > 0 且跑赢 BTC 单边。
2. 最大回撤 ≤ 10%。
3. 夏普 ≥ 2.0（扣 0.08% 成本后）。
4. Calmar ≥ 1.5。
5. 最长连亏 ≤ 5 笔。
6. 含 2024-09 极端段不亏。

### 2.2 成本可执行性（M8 额外，phase3 M8 验收 3）
- 滑点 ≥ 3–5bp（M6 已用 4bp 中值，M8 主循环必须带成本）。
- 每笔成本 ≤ 毛利 35%（`cost_model.max_cost_as_pct_of_gross`）。

### 2.3 M8 主循环组装（后端架构师方案）
```
M1 数据(ETH/SOL 410d Parquet, 9841 bar)
  → M3 信号(close_a/close_b → spread/h/z, hl_range=(368,856))
  → M4 决策(状态机 → OrderIntent)
  → M5 风控(gate → PASS/REJECT/HALT, 拒单率入 M7)
  → M6 执行(PaperBroker 4bp 滑点 + 0.1% taker → FillReport)
  → M7 监控(事件订阅, 非关键路径, 不影响撮合)
  → M8 净值曲线 / 四件套 / 2024-09 段 / golden value / 峰值·稳态双栏
```
红线（代码审查员 + 测试）：
- **t 出信号 / t+1 跨 bar 成交**（防未来函数，D8）。
- 固定种子 + 固定数据快照 golden value（防环境漂移）。
- 夏普/Calmar 注明 1h 年化口径 √(365×24)，与 1min 口径区分（D9）。

### 2.4 M8 出数后的分支（B 专家 + C 专家）
- 全绿 → 进入 M9 + 实盘开关（live_trading 默认关，需二次确认短语）。
- 某门槛不过 → 回 M4/M5 调参（**不得放宽 backtest_gate**，门槛是冻结红线），或换币对重筛（数据工程师回到 M2）。
- 峰值达标但稳态 0.5× 后跌破门槛 → 判定"因子拥挤过早衰减"，策略生命周期管理（M5 占位）启动。

## 5. 目标实现经验教训小结（沉淀进长期记忆）
1. **深数据是币对/半衰期判据的唯一准绳**：短样本会给错的币对和错的参数区间，必须以全量计算结果覆盖经验值（D1 同类教训）。
2. **每模块配验收脚本 + 全绿才提交**是本项目最低质量门槛；M8 升级为 golden value 快照防漂移。
3. **市场无关骨架 + 市场相关接口（5 ABC）**让 M4–M7 一次到位，M8 主循环零改动复用；未来换 A 股/期货只换接口实现 + 1 份市场 YAML。
4. **公式红线前置**（R1–R5）+ **非关键路径隔离**（监控告警绝不阻塞撮合）是稳定性的两根支柱。
5. **因子拥挤/AI 压缩**：M8 必须峰值/稳态双栏申报，衰减是渐进过程且被 AI 持续缩短周期，不可按峰值外推长期收益（phase4 §9.1/9.2 已固化）。
