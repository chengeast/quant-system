# 阶段 4 补充 · 跨市场可扩展架构（加密货币 → A 股 → 美股期货）

> 产出：3 金融专家（A/B/C 辩论）+ 后端架构师 + 数据工程师
> 触发：用户指出"不同市场不光策略不同，整个思路也不一样"，要求在写决策层前先定跨市场架构。
> 状态：待用户确认。确认后锁定为"换市场不换骨架"的设计基准。

## 0. 核心结论（3 专家 + 架构师共识）

**6 层骨架市场无关、可复用；真正分市场的是 5 个"市场相关"接口。**
换市场（加密→A股→期货）时：信号层公式、决策层规则、对账模块**不动**，
只替换 5 个接口的实现 + 一份市场 YAML 配置。这就是"换市场不换骨架"。

## 1. 三大市场本质差异（为什么思路不同）

| 维度 | 加密货币（MVP） | A 股 | 美股期货 |
|------|---------------|------|---------|
| 交易时间 | 7×24 连续 | T+1、有休市 | 盘前后+夜盘、有结算 |
| 杠杆/做空 | 现货双向 | 融券难、做空受限 | 保证金杠杆、天然双向 |
| T 限制 | 无 | **T+1 硬约束** | T+0 |
| 涨跌停 | 无 | ±10%/±20% 锁板 | 无（但有熔断） |
| 特有结构 | 无 | 除权/停牌 | **合约期/换月/展期** |
| 价差回归特性 | 干净但被高频卷 | 制度摩擦=回归力，但锁死风险 | 展期有制度性价差窗口 |

## 2. 统计套利（配对交易）可移植性裁决（3 专家少数服从多数）

- **逻辑本身市场无关**（协整残差平稳是纯数学，A 主张）。
- **可执行性排序（B/C 多数，2/3）**：
  1. **加密现货**：可执行最干净（24h 双腿可平、无涨跌停、发散可及时止损），但被高频卷，alpha 收窄。
  2. **美股期货**：价差空间大，但需根改"展期/换月跳空"建模（协整断裂风险）。
  3. **A 股**：制度摩擦增强回归，但 T+1+涨跌停+融券稀缺使对冲腿**发散后无法平仓**，尾部风险是"被锁死"，需根改对冲腿（用 ETF/股指替代腿）。
- **保留意见**：A 保留"A 股制度摩擦增强统计套利"观点，待 A 股数据到位后复核。

## 3. 4 模型分市场适配优先级（3/3 否决"全市场全适用"）

| 市场 | 模型优先级 | 备注 |
|------|-----------|------|
| **加密货币** | 订单流 > 波动率 > 做市 > 统计套利 | 现货已卷，做市/订单流是方向；统计套利作地基 |
| **A 股** | 统计套利(准配对) > 做市 > 订单流 | 波动率模型剔除（IV 数据缺+涨跌停扭曲）；订单流降级（逐笔数据源未备） |
| **美股期货** | 统计套利 > 波动率 > 做市 | 做市有 CME 制度红利，可升优先级；展期套利特有 |

> 对 MVP（加密）影响：**统计套利仍作地基先跑通**，但 C 专家提醒其 alpha 有限（年化 5–15%），做市/订单流是后续重点。

## 4. 五个"市场相关"接口（后端架构师技术落地）

```python
# src/core/market_ifaces.py
class MarketAdapter(ABC):          # 行情源 + 订单簿深度 + 交易源
    def fetch_kline(...) -> DataFrame: ...
    def fetch_depth(symbol, top=5) -> DepthBook: ...

class HedgeLegResolver(ABC):       # 对冲腿解析
    # 加密=直接腿；A股=ETF/股指替代腿(conv_ratio)；期货=展期腿(roll)
    def resolve(primary, signal) -> LegMapping: ...

class RegimeGate(ABC):             # regime/协整断裂检测
    # 返回 OK / BROKEN(协整断) / ROLLING(换月) / INVALID
    def check(pair, coint) -> RegimeStatus: ...

class RiskPolicy(ABC):             # 市场风控
    # 涨跌停锁死校验(A股) / 展期跳空熔断(期货) / 24h发散止损(加密)
    def gate(intent, pos, equity, book) -> RiskVerdict: ...

class BrokerAdapter(ABC):         # 撮合/滑点/保证金
    # 加密=滑点3-5bp；A股=0.3-0.5%+T+1不可平；期货=跳空+保证金
    def execute(intent) -> FillReport: ...
    def calc_slippage(intent, book) -> float: ...
```

**MarketConfig / Registry**：每市场一份 YAML 声明 5 接口实现类路径 + 交易参数；
`MarketRegistry.register("crypto_gate")` 注入，6 层骨架代码零改动。

## 5. 市场无关（可复用） vs 市场相关（每市场一套）

| 市场无关（复用 6 层） | 市场相关（每市场一套） |
|---------------------|---------------------|
| 信号层公式：协整/ADF/EG/z-score | MarketAdapter（行情源） |
| 决策层：±3σ进/0.5σ出/止损/超时 | HedgeLegResolver（对冲腿规则） |
| 对账模块：Reconciler/ReconRecord | RegimeGate（regime 检测） |
| 数据清洗/缺口检测 | RiskPolicy（涨跌停/展期/发散） |
| 紧急停止机制 | BrokerAdapter（撮合/滑点/保证金） |

## 9. 已识别未实现的风险项：因子拥挤 / alpha 衰减（用户 2026-11-07 提出）

> 用户洞察："因子/因子组使用初期指示作用强，随市场参与者使用增加而减弱。"
> 学术定位：策略拥挤（factor crowding）/ alpha 衰减 / 同质性套利。属跨市场通用风险，跨市场设计须预留。

**底层机制**
1. 同质性套利：策略公开→资金涌入→价差在阈值前被抹平，回归变快变薄，收益摊薄
2. 自我消解：套利行为本身改变被套利对象的统计性质
3. 拥挤→踩踏：regime 切换时同步平仓，反向流动性枯竭，尾部风险放大

**对 4 模型的拥挤度风险标签（多数意见 + C 专家修正）**
| 模型 | 拥挤度衰减风险 | 说明 |
|------|--------------|------|
| 统计套利（协整内核） | 中（低） | 协整关系存在即有 alpha，衰减较缓；但"流动性错价"部分随拥挤衰减 |
| 做市 | 高 | 对手盘即高频机构，"公开"≈"立刻被卷" |
| 订单流 | 高 | 微观结构因子公开即失效最快 |
| 波动率交易 | 中低 | IV 数据成本高天然过滤部分参与者；IV/HV 差值回归相对独立 |
> 修正：方向性/因子类（动量/价值/订单流）拥挤衰减最猛；统计套利协整内核衰减慢，流动性错价部分一样被卷。

**待落地措施（当前 MVP 不阻塞，记录为后续）**
1. 监控层加 **alpha 衰减监控**：连续 N 周"信号强度 vs 实现收益比"下降 → 预警，人工复核（不自动平仓）
2. 信号层 **滚动 re-estimation**：协整/半衰期/σ 阈值定期重算（已要求数据驱动，此为延伸）
3. 风控层 **策略生命周期管理**：MVP 跑通→持续监测衰减→衰减到门槛下停用/换因子
4. 拥挤度量化指标候选：信号-收益比、价差回归速度、换手率放大、价差 σ 压缩

**跨市场复用**：A 股散户多、做市不发达，拥挤度逻辑与加密完全不同；美股期货有 CME 做市商制度。本框架（拥挤度标签 + 衰减监控 + 生命周期管理）三市场通用。

### 9.1 用户补充（2026-11-07）：衰减有时间维度，且被 AI 持续压缩

> 用户原文："过程还是比较长的，但是随着 AI 技术的推广，这个过程也在不断缩短。"
> 这条把风险从"会不会发生"修正为"以什么速度发生"。两条结论：

**（1）衰减是渐进过程，而非阶跃——MVP 跑通时≠峰值时**
- 策略上线初期，参与者尚未全部涌入，价差仍有合理空间，alpha 处于高位。
- 随采用率上升，回归速度加快、毛利摊薄，alpha 缓慢衰减（非一夜归零）。
- 工程含义：**MVP 跑通时的回测收益是"峰值期"，不可直接外推为稳态收益**。回测报告的"可持有收益"必须做衰减折减（保守取 0.5×峰值 起步，或按历史类似策略衰减曲线折算），而非按峰值申报。

**（2）AI 推广正在缩短衰减周期——衰减速度是"变量"，不是"常数"**
- 传统：因子从论文/书→实盘→被卷，周期 1-3 年。
- AI 时代：因子逻辑、信号代码、回测框架门槛骤降，参与者涌入速度加快，周期缩短到 **数月**（甚至更短）。
- 工程含义：**"多久衰减一次"本身在变，不能设死一个固定 re-estimation 周期**。衰减监控必须是动态的——
  - 不设固定的"重估间隔"（如"每季度重估"），改为**滚动窗口 + 突变检测**：当 60 天滚动窗口的信号-收益比斜率明显下倾，触发一次重估（而非到点才重估）。
  - 设一个"衰减速度观测指标"：同因子在不同市场周期内的衰减半衰期对比。若观测到 AI 扩散后衰减半衰期缩短（例如从 12 个月 → 6 个月），则自动收紧重估窗口。
  - 跨市场验证：A 股散户多、AI 普及度不同，衰减曲线可能与加密差异大，须各市场独立观测，不可套用。

### 9.2 措施优先级修正（基于 9.1）

原 4 项措施优先级调整：

| 措施 | 原优先级 | 修正后优先级 | 原因 |
|------|---------|-------------|------|
| 1. 滚动 re-estimation（信号层） | 低（远期） | **高（M4 起内置）** | 9.1(1) 要求峰值≠稳态，滚动重估是防"外推峰值"的第一道防线；不再是"定期"，改为"突变检测" |
| 4. 拥挤度量化指标 | 低（远期） | **高（M4 起内置）** | 9.1(2) 要求衰减速度本身可观测，必须把"信号-收益比斜率 + 价差回归速度 + 价差 σ 压缩"做成可监控指标 |
| 2. alpha 衰减监控（监控层） | 中 | **中（M7 实现）** | 监控层落地，但须基于 9.2 的高优先级指标，而非固定周期 |
| 3. 策略生命周期管理（风控层） | 中 | **中（M5 占位）** | 设计预留"衰减到门槛→停用/换因子"的接口，M5 风控层先留 hook |
| 5. **衰减折减回测**（M8） | 新增 | **高（M8 实现）** | 9.1(1) 的工程直接落点：回测报告分两栏——"峰值收益"与"保守稳态收益（0.5×峰值）"，稳态收益才是决策依据 |

**最小可行落地（M4 阶段）**：
- 信号层 `mean_reversion_signals.py` 加 `rolling_reestimator` 钩子（不写实现，留接口）：`reestimate_trigger(slope_threshold, window)` —— 60 bar 窗口内 z-score 信号强度斜率跌破阈值 → 重算 μ/σ/h。
- 拥挤度指标（4 项）落到 `config/strategy_params.yaml` 的 `monitoring` 段：`alpha_decay_monitor: {slope_window: 60, decay_ratio: 0.8, slippage_ratio_window: 30, sigma_compression: 0.7}`（数值暂定，待 M8 回测数据校准）。
- M8 回测报告加"峰值 / 稳态"双栏，稳态 = 峰值 × 0.5 起步。
