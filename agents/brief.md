# 项目输入条件（全体角色共享 brief）

> 本文档是 10 个角色讨论的**共同前提**，任何人不得偏离。

## 来源
基于 Mark 说海外视频号（2026-09-17）提出的「对冲基金策略体系」，拆解为 4 模型 / 6 层 / 6 阶段 / 10 角色。
用户认同其分析框架，但要求逐条核实准确性，不盲从。

## 已确认的决策
| 项 | 决策 |
|----|------|
| 交易对象 | 加密货币（MVP 起步），后续扩展 A 股 |
| 数据源 | Gate.io API（用户提供 APIKEY）；A 股历史数据用户可提供，实时数据靠东财爬虫（后期） |
| MVP 范围 | 先做**统计套利（配对交易 / 均值回归）**，后续叠加做市、订单流、波动率模型 |
| 币种对 | **不锁定**，由数据工程师用 Gate.io 历史数据做相关性/协整筛选，选出统计最稳的一对 |
| 回测数据粒度 | Gate.io K 线（OHLCV），1分钟/5分钟/1小时级别 |
| 交付物位置 | GitHub 仓库（用户账号待确认） |

## 4 个模型（决策层可挂载的策略）
1. **套利 / 统计套利**：关系稳定的资产组合 + 价差均值回归（配对交易，非跨所搬砖）
2. **做市**：双边报价赚买卖价差，承担库存/逆向选择风险，风险与利润不成正比
3. **订单流**：订单流不平衡（主动买/卖单相对强度）预测短期价格
4. **波动率交易**：隐含波动率 vs 历史波动率的预期差（均值回归套在波动率维度），非"波动率长得像历史"

## 6 层架构
数据层（可信行情）→ 信号层（可检验指标）→ 决策层（进出规则）→ 风控层（订单能否发出）→ 执行层（确认执行+对账）→ 监控层（异常通知）

## 6 个阶段
1. 头脑风暴（对象/目标/规则/约束）
2. 架构讨论（模块边界/数据结构/异常处理）
3. 项目计划（拆小模块+验收标准）
4. 构建/测试/整理
5. 审查（逻辑/数学/边界/代码）
6. 上线（回测/模拟/小规模评估/监控）

## 10 个角色
PM、后端架构师、测试工程师、代码审查员、数据工程师、调试员、前端工程师、运维、性能/可观测性、安全工程师
（调试员职责可由测试工程师兼任，但流程中保留该角色）

## 约束（硬边界）
- 密钥/APIKEY 不进代码仓库，用 .env + .gitignore
- MVP 阶段只做**模拟/回测**，不做实盘
- 所有结论必须带数据支撑，不允许"我觉得"
- 加密货币单交易所（Gate.io）起步，跨所套利 MVP 不做（价差薄、拼不过高频）
