## Q1 · carry 收益太薄，从风险派视角，carry 策略的最大风险是什么？

**结论：最大风险不是"funding 方向突变"，而是 carry 收益（年化 +3%）相对单期价格下行 + 成本的结构性脆弱——即"赚小钱亏大钱"的尾部不对称。** 三类风险按严重度排序：

1. **持仓期拉长后的市场下行风险（最核心）**
   - carry 年化 +3.0%（BTC）= 169d 窗口 × 均值 2.7e-05 × 3 × 365（`funding_all_coins_169d` 回读）；为覆盖 taker 0.1%/笔的 roundtrip 0.2% 成本，**必须长期持仓**（`phase9-g1-carry-data-feasibility.md` §2.2 关键发现：高频交易会被成本吞没，需降频或 maker）。
   - 长期持仓 = 敞口在价格 β 上持续暴露。BTC 单期 -5% 的回撤（8h 结算粒度下的日常波动）就已**吞掉近 2/3 的年化 carry 当量**，且会反复累积。carry 是"利差型"收益，价格波动是"绝对型"风险，二者不对冲——持仓越久，价格下行尾部越容易把"薄 carry"打穿为净亏。
   - 这正是我（B 派）的核心信条：统计套利/利差策略"赚小钱亏大钱"的尾部风险被普遍低估。

2. **做空 carry 币对的尾部风险（空头敞口尾部更肥）**
   - 做空 SOL/XRP/AVAX/ADA/BCH 这类负 carry 币对，本质是"持有空头永续 + 多头现货"的期现套利反向结构。空头在加密市场的尾部**肥尾 / 跳空风险远大于多头**（逼空、流动性真空、资金费率极端为负后的反向）。
   - BCH 负 carry 年化 -10.7%（`funding_all_coins_180d` 回读，mean -9.6e-05）是 9 币中最大绝对值：若做空 BCH 方向 funding 收入为负（`phase9` §2.2 "方向错误"），则**收益项直接为负**，叠加空头价格尾部 → 双重下行。这是 9 币中尾部最肥的一条腿。

3. **funding 方向突变（次要，但须监控）**
   - 正占比：BTC 74% / DOGE 72% / LTC 53% / ETH 63%（`funding_all_coins_180d` 回读）。**LTC 正占比仅 53%** 意味着 funding 经常为负，carry 收益项本身不稳定；BTC 74% 也非 100%，存在连续负 funding 窗口 → carry 从"赚 3%"转为"付 funding"，收益项在单期可转负。
   - 突变本身不致命（单次 8h 结算幅度小），致命的是"收益项转负 + 价格下行"叠加。

> 风险派一句话：carry 薄 + 持仓长 + 空头肥尾 + funding 正占比非 100% → 该策略的风险收益比天然偏向"小赚大亏"，**必须先设硬止损 + 敞口上限 + funding 突变熔断，再谈回测**（见 Q4）。

## Q2 · 180d 窗口 + 4h/1d 粒度，样本量够不够做尾部检验？极端段无法验证意味着什么？

**结论：1d 粒度（180根）做尾部检验样本不足；4h 粒度（1080根）勉强可做分布拟合但尾部置信度低；极端段(2026-02)无法验证 = 风险管理上的结构性盲区，"不亏"门槛退化为不可证伪。**

1. **样本量对尾部检验的适配性**
   - **1d = 180 根**：尾部检验（如极端分位、极值理论）在 180 个观测下，1% 分位仅 ~1.8 个样本、0.5% 分位 <1 个样本——**尾部基本不可估**。1d 粒度不能承载任何尾部结论。
   - **4h = 1080 根**：1% 分位 ~11 个样本、0.5% 分位 ~5 个样本，分布拟合（如 t 分布 / GED 厚尾指数）可做，但**尾部参数的统计误差大**，对"极端段 2026-02"这类历史罕见事件无覆盖力。
   - **对照锚点（盘上既有事实）**：F-1 三套网格均值回归切片在 6 条冻结门槛下全部 0 达标、门槛全程未放宽（`f1_expert_A/B/C_opinion.md` + `phase5-p7-final-summary.md` 既有共识）；且冻结门槛第 5 条"极端段不亏"在 15m/30m 短周期下本就"不可评估（N/A，未擅自改门槛）"（`phase5-p4-scale-probe.md` §1.2/§3.1）。**180d 窗口的 4h/1d 样本量与此同构——尾部检验在统计学上不可靠**，极端段在 G1 carry 上更是因 180d 数据缺口而完全无覆盖。

2. **极端段(2026-02)无法验证的风险管理含义**
   - 6 条冻结门槛中第 5 条是"极端段(2026-02)不亏"（`dispatch_queue.md:51`）。funding 180d 限制 → 该段 funding 数据**根本不存在**（`fr_btc_260d.json` 400 错误），故该门槛在本轮 **不可验证、不可证明"不亏"，也不可证明"亏损"**。
   - 风险管理含义（非"可以忽略"）：
     - ① **不能把"无法验证"当"通过"**（数字纪律：N/A 占位不当通过）。它既不是 ✅ 也不是 ❌，而是"该门槛本轮不成立"。
     - ② 这意味着任何 180d 窗口回测**只承担"carry 年化 + 单笔成本覆盖"的验证，不承担尾部验证**（尾部由 2026-02 承担，但该段无数据）。
     - ③ 因此本轮回测结果**永远无法单独证明"策略能穿越极端段不亏"**，上实盘后极端段不亏只能靠**实盘监控门槛**（前 N 天逐 8h funding + 回撤熔断）承接，而非回测证明。
     - ④ 这是**结构性数据缺口**（Gate.io 平台 180d 边界，`phase9` §四 缺口清单 🔴 高），不是"多拉一次数据"能补的——须换数据源（见 Q3 ④）或降级处理。

> 风险派一句话：180d/4h/1d 的样本量对尾部检验**统计上不足**，极端段又因 180d 限制而**完全不可评估**——本轮任何"达标"结论都**不能**作为"能穿越 2026-02 极端段"的依据。

## Q3 · 本轮先测哪一类？（明确选一项 + 理由）

> 选项：① G1 carry（180d + 4h/1d，做多 BTC/ETH/DOGE/LTC） ② G2 订单流/做市 ③ G3 波动率/尾部对冲 ④ 换数据源补全 funding 410d 再测 ⑤ 放弃 G1

### 我选 ① G1 carry（做多 BTC/ETH/DOGE/LTC，180d + 4h/1d 粒度）

**注意：选 ① 不等于"推荐 carry 是好策略"，而是"在风险可控前提下，① 是唯一本轮可测且尾部风险可管理的选项"。** 理由逐条：

1. **为什么选 ①（可测性 + 风险可管理性最优）**
   - ① 是唯一**本轮即可落地**的选项：数据已落盘（`_g1_probes` 7 个 JSON + 本地直连实测），M5–M8 接口可复用（`phase9` §5.1），不改 `config/`、不放宽门槛即可跑。
   - **只做"做多 BTC/ETH/DOGE/LTC"这一侧，不做"做空 SOL/XRP/AVAX/ADA/BCH"**：多头 carry 的尾部**肥尾程度 < 空头**。Q1 已论证空头腿（尤其 BCH 负 carry -10.7%）尾部最肥，故本轮**砍掉做空侧**，只测多头 carry 4 币，把最大尾部风险源先隔离。这是 ① 的风险收敛做法，不是全量 ①。
   - 4h/1d 粒度（`phase9` §六.2：1h 粒度 carry 不成立）→ 降频使单笔成本 0.2% 可被 3%/yr carry 覆盖，**尾部暴露的持续时长可控**。

2. **为什么不选 ② G2 订单流/做市**
   - ② 当前**无数据、无骨架、无成本模型**（`f1_expert_C_opinion.md`：M8 毛利 $107.93 vs 成本 $192.54，成本/毛利 1.784，滑点清零后 1.53 仍远超 0.35 门槛）——做市在当前成本结构下**已被证伪 0 达标**，且做市本身是"尾部肥 + 流动性真空暴露"的最差风险形态，**不符合风险派"宁可少赚不可深亏"的信条**。先测 ② 等于把最肥的尾部风险推上本轮。

3. **为什么不选 ③ G3 波动率/尾部对冲**
   - ③ 本身**就是尾部管理工具**，它的价值要**依附于一个有尾部风险的主策略**才有意义。若本轮先测 ③ 而无主策略，等于"造对冲工具但没东西可对冲"。逻辑顺序应是：**先有 ①（多头 carry 主策略）→ 再用 ③（波动率/对冲）管理 ① 的尾部**。③ 是 ① 的配套，不是先决项。

4. **为什么不选 ④ 换数据源补全 funding 410d 再测**
   - ④ 是**最理想但本轮不可行**：`phase9` §六.4 明说"funding 180d 限制是 Gate.io 平台限制，非数据拉取问题 → 更长历史需换数据源（CCXT 聚合 / 交易所 API 历史）"。但换数据源涉及**新数据管道 + 新成本模型 + 时间**，本轮任务单限定"不跑回测、不改代码、不提交 Git"，④ 超出本轮可执行边界。④ 应作为**下一轮的补强**（见 Q5 保留意见），而非本轮先测项。

5. **为什么不选 ⑤ 放弃 G1**
   - ⑤ 放弃了**唯一可测且尾部可管理的选项**，在 ④（换数据源）尚不可行的前提下，直接放弃等于**本轮无产出**。风险派反对"无脑放弃"，但**支持"带硬止损地做 ①"**——若 ① 跑完仍 0 达标，则 ① 自然转入"放弃/存档"，无需预设 ⑤。

**综合：选 ①（仅多头 BTC/ETH/DOGE/LTC 侧，4h/1d，180d），配合 Q4 风控前置条件 + Q5 保留意见（④ 换数据源作下轮补强、③ 作 ① 的配套对冲）。**
